## Pinning, rotation and rollback policy
Verifier caller supplies independently administered chain/system pins, public keys keyed by explicit keyID, counter validity windows, and (for genesis) exact externally pinned checkpoint hash. For continuation, caller supplies previously retained trusted checkpoint **outside tested DB/file sink**. Signed hash/counter/time must extend that predecessor. Counter gaps may occur when observation/signing/retention fails; strictly increasing, not consecutive. Loss of latest retained checkpoint weakens rollback detection; fail closed for normal export until independent recovery, never load sink's newest file as truth.

Rotate by separately approving/pinning new public key and activation counter; keep retired public keys and historical counter windows so retained predecessors remain verifiable. Retired private keys should be destroyed according to operator policy. Never learn a new key from sink/DB. Emergency key compromise requires independently published distrust/recovery boundary, not silently signing a new genesis. Public pins themselves require trusted distribution and protection.

## What is and is not detected
Fixtures independently construct signatures/events; tests reject alteration, insertion, order change, interior deletion, truncation below retained head, internally valid alternate chain vs pinned hash, checkpoint rollback/replay/fork, wrong key/identity, noncanonical/bounded inputs. Legitimate sequence gaps survive. Ledger hashes do **not bind sequence labels**; increasing intermediate sequence renumbering that preserves order/head cannot be distinguished from legitimate allocation gaps. Do not infer deleted events from every absent sequence.

Valid supplied suffix is checked for local continuity/projected field consistency, but any suffix after latest independently retained head is unanchored and can disappear/rewrite without retained proof. No checkpoint proves every action was logged, truthful event semantics, independent clock, or honest signer/runtime/DBA. DB/signer compromise before observation can sign fabricated history; compromise of pin/last-checkpoint retention defeats this trust model. Observation time is DB clock, not trusted timestamp authority. Forks sharing one prior checkpoint are detected when compared to the independently retained branch; a verifier shown only one branch cannot discover a hidden branch.

Single-directory lock serializes cooperative local exporters, **not** a global cross-process retention protocol: different sinks or reused stale retained predecessors can fork despite increasing DB counters. Actual production exporter requires one externally enforced signer/retention authority, compare-and-set predecessor acceptance, durable independent receipt/state and crash recovery; local lock or same-DB counter alone is insufficient. No DB/file atomicity or cross-replica guarantee claimed.
